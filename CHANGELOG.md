Добавлены property-based тесты на edge-cases `stripLiterals` (`mut`, `\'`, ``\\\\``, unterminated).

- **Логгер:** `src/utils/logger.ts` — единый stderr-выход с авто-редактированием секретов; index.ts переведён на него.
- **Stryker в CI:** отдельный job `mutation` на PR, отчёт публикуется как артефакт 30 дней. Текущий mutation score `sql-safety.ts` 75.94%, `serialization.ts` 86% (без ignoreStatic).
- **Dockerfile smoke в CI:** отдельный job `smoke` на PR — собирает образ и опрашивает `/health`. Docker-образ для GHCR публикуется на теге `v*` (linux/amd64 + linux/arm64).
- **`SECURITY.md` стал полноценным threat model.** 7 строк → 71: supported versions с источниками, 3 reporting-канала с таймлайном, in-scope/out-of-scope таблица с привязкой к коду, 6 operating requirements, 4 known limitations.

- **Ленивая загрузка:** `mysql2` (40 мс), `yaml`, `fast-xml-parser`, ~10 data-модулей через `src/utils/lazy-module.ts`. Старт 169 → 76 мс (−55%), RSS 90 → 71 МБ.

## 1.5.0

Ломающих изменений нет. Изменения поведения: `maria_execute_query` и `maria_get_table_data` маскируют значения колонок-секретов (обойти можно через `include_sensitive: true`), а версия сервера теперь берётся из `package.json`, а не из литералов в коде.

- **Гигиена: версия сервера берётся из `package.json`.** `server.ts`, `get_server_capabilities` и `get_project_health` больше не содержат литерал `1.4.0` — новый `src/version.ts` ищет ближайший `package.json` вверх от своего файла, поэтому работает и из `src/` (tsx, тесты), и из `dist/` (опубликованный пакет). Раньше версия правилась в трёх местах и могла разойтись с пакетом. Устаревшие строки husky в `.husky/pre-commit` (ломающие husky 10) удалены, `prepare` переведён на `husky`. Добавлен CI-job **Dependency audit** (`npm audit --omit=dev --audit-level=high`), и `npm audit fix` закрыл найденные уязвимости транзитивных `js-yaml` и `qs` — теперь `npm audit` чистый.

- **Аудит БД и секретов: значения колонок-секретов больше не отдаются по умолчанию.** `maria_execute_query` и `maria_get_table_data` заменяют значения колонок вида `password`, `password_hash`, `api_token`, `token_hash`, `secret_key` на `***` и сообщают их список в `redacted_columns` — ИИ-агенту больше не нужен полный дамп `cms_users`, чтобы понять схему. Вернуть значения можно только явным `include_sensitive: true`. Эхо-запрос теперь проходит через `redactSecrets`, а сам `redactSecrets` научился маскировать секреты в JSON/INI (`"password": "..."`), учётные данные в URL (`mysql://user:pass@host`) и `Authorization: Basic`. Отдельная находка: оба CLI-скрипта (`install-instantcms.mjs` и `verify-generated.ts`) передавали пароль MySQL аргументом `-p<password>`, что видно другим пользователям в `ps`; теперь они пишут временный option-файл с правами `0600` и удаляют его при выходе (включая `SIGINT`/`SIGTERM`). Покрыто тестами `src/__tests__/maria-regression.test.ts`, `sql-safety.test.ts` и `scripts-secrets.test.ts`.

- **`scaffold_filter` умеет фронтенд-фильтр списка.** Опция `frontend: true` добавляет к бэкенд-гриду помощник `<Name>Filter` с методами `getFields()`, `apply($model, $request)` и `getQuery($active)`. Поля строятся на `cmsFormField` и применяются ядром через `applyFilter()` — тот же механизм, что в контроллере `content` (`public $list_filter`), поэтому фильтр работает по-настоящему: строковый фильтр даёт `filterLike`, числовой диапазон — `filterGtEqual`/`filterLtEqual`, список — `filterEqual`. Для `select`/`multiselect` теперь обязательны `options`, иначе вместо нерабочего поля генератор падает с понятной ошибкой. Проверено на живом InstantCMS новым сценарием `filter` (3 материала: без фильтра — 3, по заголовку — 1, диапазон цены `от 150` — 2) и юнит-тестами.

- **CRUD-материалы теперь можно адресовать по ЧПУ.** `scaffold_crud` получил опцию `use_slug`: она добавляет в `install.sql` колонку `slug` с уникальным ключом, поле `slug` в формы с правилом `slug`, метод `getItemBySlug()` в модель, файл `routes.php` и метод `route()` в контроллер (без него ICMS2 не читает `routes.php`), а также переводит ссылки списка и редиректы на `/{controller}/<slug>.html`. ## 1.2.1

- Significantly expanded automated test coverage: 179 new tests across 13 suites (from 272 to 451 passed), covering property-based serialization/pagination, scaffold-addon round-trip for all 5 types, project workflow edge cases, knowledge lookups, artifact ZIP handling, db-tool invocations, MCP integration smoke, and performance baselines.
- Introduced `defineTool` and `defineToolWithManualResult` helpers in `src/utils/define-tool.ts` to normalize the MCP result contract; exceptions in handler now produce a structured `errorResult(TOOL_EXECUTION_ERROR)` instead of leaking.
- Refactored `find_tool` to use token-based matching with priority scoring (exact > prefix > substring), returning a `ranked` array with `score` and `matchedTokens` for transparency.
- No runtime/tool surface changes; the public MCP contract is fully backward compatible with `1.2.0`.
