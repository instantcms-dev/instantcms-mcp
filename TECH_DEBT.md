## Открытый техдолг

Каждый пункт — конкретная задача с местом в коде и acceptance criteria. Никаких «улучшить», только измеримые действия.

### T1. Расширить `SECURITY.md` до полноценного threat model

**Где:** `SECURITY.md` (сейчас 425 байт, 7 строк).

**Что добавить:**

1. Поддерживаемые версии: Node (текущее заявленное `>=18`), версия InstantCMS (текущая `2.18.2`).
2. Чёткий приватный канал для отчётов (не «report privately»): email/Security Advisories GitHub.
3. Disclosure policy: окно ответа, ожидаемый таймлайн фикса.
4. **Threat model** — что мы защищаем и что **не** защищаем:
   - **Защищаем:** trust boundary между MCP и БД (sql-safety), секреты в логах (redactSecrets), выход MCP-протокола (массив в structuredContent), stateful HTTP-сессии (rate-limit, auth).
   - **Не защищаем (явно):** XSS в сгенерированных `.tpl.php`, SQL вне MCP-границы (если пользователь обходит инструменты), сгенерированный PHP до того, как пользователь его провалидирует.
5. Требования к пользователю: запускать на доверенном хосте, не включать `MCP_HTTP_HOST=0.0.0.0` без reverse proxy, не публиковать токен в логах.

**Acceptance:** `wc -l SECURITY.md` ≥ 50; каждый раздел имеет конкретное содержание (не bullet «see docs»).

**Усилие:** 1 час.

**Статус:** [x] **(закрыто 2026-09-19, коммит в этой сессии)** — `SECURITY.md` расширен с 7 строк до 71: supported versions с источниками, 3 reporting-канала с таймлайном, in-scope/out-of-scope threat-model-таблица с привязкой к коду, 6 operating requirements, 4 known limitations.

### T2. Удалить TODO в `scaffold-tool.ts`

**Где:** `src/tools/scaffold-tool.ts:305` — единственный TODO во всём `src/`.

**Что:** либо реализовать логику, либо удалить TODO, либо заменить на конкретное исключение с понятным сообщением. Сейчас `// TODO: ваша логика` — это либо заготовка разработчика, либо забытый код.

**Acceptance:** `grep -rn 'TODO' src/` возвращает 0 строк.

**Усилие:** 15 минут.

**Статус:** [x] **(закрыто 2026-09-19, коммит в этой сессии)** — TODO оказался **PHP-комментарием внутри генерируемого шаблона hook'а** (`on${Name}${hookCamel}.php`), а не нашим техдолгом. Это документированный плейсхолдер для разработчика дополнения, такой же легитимный, как `return $data;` рядом. Acceptance «grep TODO = 0» нерелевантен для генерируемого кода.

### T3. CI: прогон Stryker как отдельный job

**Где:** `.github/workflows/`. Сейчас Stryker (`stryker.config.json` + `npm run mutation:test`) запускается только локально и **не в CI**. После наших правок это регрессионная защита критичных утилит — терять её между релизами нельзя.

**Что:** добавить job `mutation` в `ci.yml`, который запускает `npm run mutation:test` (timeout 15 минут) на Node 20 (Stryker 10 требует Node 20+). Не блокировать merge, но публиковать HTML-отчёт как артефакт и комментировать в PR через `gh-actions-artefact`.

**Acceptance:** job виден в CI, отчёт доступен 30 дней.

**Усилие:** 30 минут.

**Статус:** [x] **(закрыто 2026-09-19, коммит в этой сессии)** — добавлен job `mutation` в `.github/workflows/ci.yml`: Node 20, триггер только на PR, не блокирует merge, HTML-отчёт как артефакт 30 дней. `reports/` в `.gitignore`.

### T4. CI: проверить Dockerfile в `docker.yml`

**Где:** `.github/workflows/docker.yml`. Уже триггерится на изменения `Dockerfile`, но собирает только на тегах. На PR собирает, но не валидирует запуск.

**Что:** добавить `docker run --rm <image>` с healthcheck-проверкой (`curl /health`) как отдельный шаг PR-job. Закрывает риск «Dockerfile компилируется, но контейнер не стартует».

**Acceptance:** при изменении `Dockerfile` в PR-job запускается контейнер и проверяется `GET /health` → 200.

**Усилие:** 30 минут.

**Статус:** [x] **(закрыто 2026-09-19, коммит в этой сессии)** — добавлен job `smoke` в `.github/workflows/docker.yml`: build с `load: true`, контейнер на 13001, цикл `curl /health` 30 секунд. Только на PR, не блокирует publish.

Идемпотентно: скрипт можно прогнать повторно и закоммитить diff.

## Не техдолг

Сознательно **не включаем** в этот список — не потому что неактуально, а потому что не имеет смысла делать:

- **«Снизить количество `as any`»** — сейчас в `src/` 9 кастов `as unknown as`, все оправданы конфликтом zod v4 ↔ SDK generic. Не bug, не долг.
- **«Довести coverage до 95%»** — текущие 89.5% statements + 90% для `src/utils/` уже выше индустриального медиана (60–70%). Следующий процент даётся дороже предыдущего.
- **«Вынести генераторы в чистые модули»** — 17k строк в `src/tools/`, но 100 инструментов покрыты контрактным тестом. Рефакторинг ради рефакторинга, не закрывает реальный пробел.
- **«Coverage в `npm run check`»** — мы **уже решили** не делать: это удлиняет check на 50% и блокирует merge по шуму. Coverage проверяется в CI отдельным job.
